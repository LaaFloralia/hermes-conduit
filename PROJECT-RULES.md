# LAA app project rules

- Start with `docs/laa/SESSION-HANDOFF.md`: current state, team, the owner's open issues and the merge gate. The owner calls this project "AIアプリ" or "LAAアプリ".
- Staffing (the owner, 2026-11-08): the parent keeps the model the owner selected for it. 委譲は /Users/laa/hq/guide/models.md の分担表に従う。 Delegated work runs as a subagent in the parent's own workspace and session (`hq/tools/RUNTIME.md`); no child-only workspace, detach or independent CLI worker. Independent review is not the default: only record overwrites or deletions, auth and secrets, and money, when the parent decides a second lineage is needed.
- Show the owner the LAA names from `hq/tools/HARNESS.md`「名称の辞書」 (LAA, Work, AI社員) through the build-time copy layer (`scripts/laa/brand-bundle.py`, `brand-copy.json`; AppIntent literals use its alias keys). Keep the upstream string catalogs, lookup keys, protocol and notification match strings, identifiers and license text unchanged (2026-11-08).
- Design and verify for the owner's single-screen iPhone 16 Pro Max (440 × 956 pt). The owner does not use iPhone Duo; do not test on it.
- Simulators on this Mac: the `LAA 16 Pro Max` simulator (iOS 27.0, the owner's device) is the default for UI tests and screenshots. Keep the compact 440 × 956 pt snapshot tests, such as `LAACompactChatSnapshotTests`, and confirm on the real device through TestFlight. Do not add simulator runtimes without the parent session's approval.
- Across the shared Mac, one `xcodebuild` runs at a time (`/Users/laa/hq/harness/build-slot.sh`, `-jobs 4`), and its own simulator is booted only for that run and shut down immediately after testing. Release builds use the external APFS workspace; iPhone App Store Connect processing does not hold the build slot. Check `laa-storage-guard status` and keep at least 80 GiB free.
- Export attachments from one `xcresult` one call at a time: concurrent `xcresulttool export` runs on the same bundle race on its index and fail.
- Keep generated output out of git: `.deriveddata*`, `*.xcresult` and `build/` never enter a commit. Stage the files you own by name instead of `git add -A` (a worktree's DerivedData sits beside the sources), and read `git diff --cached --name-only` before committing.
- Merge one candidate at a time. Require GitHub CI and the LAA personal build on the candidate. GitHub CI selects tests with `--changed-from HEAD^1`; integration candidates also require the selected smoke tests locally with `--changed-from <master SHA>`.
- Compare candidate and master on `LAA 16 Pro Max`; the known smoke failures are listed in the handoff's merge gate. New failures block the merge. Judge every check, build and test by its exit code and its saved full log (tests: the result bundle's pass/fail counts), never by a tail of the output, and name that log in the report.
- Judge visual consistency on the rendered result of every row and state, not on the shared component: after BUS-385's meter unification, rows with tick marks still drew a 12 pt bar.
- On Mac the main window's scene is already active at launch, so `onChange(of: scenePhase)` never reports that first activation; handle the initial phase as well as changes. Acceptance includes opening an employee chat right after a cold launch, not only after a resume (2026-11-09).
- Take "before" screenshots of an old SHA from a separate worktree. `git checkout <old SHA> -- <files>` in the working copy overwrote an uncommitted fix (2026-11-09).
- Accept a Mac control by clicking it and checking the result, not by its presence. On Mac a toolbar item that holds a button and a Menu side by side collapses into one Menu, so the call button opened the conversation menu in 2611090507; give such controls separate toolbar items on Mac.
- In UI tests, find the app's controls by accessibility identifier, not by label: `app.buttons["Dictate"]` also matched the keyboard's dictation key.
- This repo is public. Keep private URLs and identifiers out of it and embed them at release time from `~/.config/laa/mac-release.env.tpl` into Info.
- GitHub CI currently does not run on pushes to master (BUS-323). Until it does, and whenever GitHub Actions is unavailable, gate on the local master-based smoke with no new failures and a local personal Release build: generate `project-personal.yml` and build for generic iOS with `CODE_SIGNING_ALLOWED=NO`.
- The parent session runs TestFlight uploads because it holds the required secrets.
- Do not add direct Foundation `Date <=` or `Date >=` comparisons; use equivalent `<` comparisons. With Xcode 27.2 these operators left weak Foundation imports in a shipping binary even after simulator and personal Release builds passed. Before export or upload, run `scripts/laa/check-weak-date-ops.sh` on every shipped app and extension, covering every architecture. A successful build alone does not pass this gate.
- Install launchd services such as the push relay (`scripts/laa/relay-install.sh`) only from the main checkout `/Users/laa/dev/hermes-conduit`, never from a worktree; worktrees are removed after merges.
- Upstream `Conduit` plugin updates are decided by the daily HQ routine in `hq/tools/APP-UPDATE.md`. The LAA build shows no plugin update notices.
- Publish `focusedSceneValue` only on Mac. On iPhone every `TabView` tab stays resident, so all tabs write the value at once and the app froze after closing Settings in Chat (TestFlight 2611091726, fixed in 2611092009).
- Design: Georgia is for Latin text only; Work's sub-pages sit in the sidebar's second level; the tab name "Chat" is intentional, and Mac uses the same name.
- Bridge stores parse their whole file on every `get` and `all`. Read once per pass and index in memory; a `get` per row inside a loop made one daemon sync cost seconds (2026-11-14).
- After a provider change the daemon returns the archived agent's timeline empty. The turns before the change come from the snapshot written at the change (`session-handoffs/<session>/<new agent>.json`), never from re-reading the old agent.
- Work has two session lists, the phone's (`LAAWorkSessionsSection`) and the Mac's (`LAAWorkDesktopSessionsView`). A change to what a list shows or when it re-reads is checked on both: the Mac's had no periodic re-read while the phone's ran every five seconds.
- Check session behavior against the real Bridge in the running app with one disposable conversation, archived afterwards. An isolated Bridge cannot create a session: the delegation entry refuses a session an agent starts, and that control is not worked around.
